Insights Page Layout

Which layout structure works best for the /insights page?

A

Single Column — Scrolling Narrative

Full-width sections stacked vertically. Each section tells part of the story: clusters → demand → gaps → learn topics. Like a data report you scroll through.

Summary Bar — 12 realistic targets · 2 role profiles · 4 high-demand gaps
Job Clusters — full width cards showing 2-4 clusters
Demand Patterns — full width bar chart
Gap Analysis — full width: gaps vs bridges vs strengths
Study ROI — recommended topics with "Generate Guide" buttons

Pros

  • Simple, no layout decisions
  • Each section gets full width
  • Natural reading flow (top → bottom)

Cons

  • Long scroll to reach Study ROI
  • Can't see clusters and demand side-by-side
B

Dashboard Grid — Clusters Drive Everything

Clusters are the hero section. Clicking a cluster filters demand patterns and gaps below it. Two-column grid for demand + gaps side by side. Study topics at the bottom.

Summary Bar — 12 realistic targets · 2 role profiles · 4 high-demand gaps
🎯 Job Clusters (hero) — clickable cards, "All" tab + per-cluster tabs
Demand Patterns
filtered by selected cluster
Gap Analysis
filtered by selected cluster
Study ROI — topics filtered by cluster context

Pros

  • Interactive — cluster selection drives the whole page
  • Demand + gaps visible together
  • Answers "what does THIS type of role want?"

Cons

  • More complex state management
  • Cluster names need to be good or it's confusing
C

Tabbed Sections — One Focus at a Time

Summary bar at top, then tabs: Clusters | Demand | Gaps | Study. Each tab is a focused, full-page view. No scrolling past unrelated sections.

Summary Bar — always visible at top
Clusters
Demand
Gaps
Study
Active tab content — full page for each section

Pros

  • Clean, focused view per section
  • No scroll fatigue
  • Easy to add new tabs later (extensible)

Cons

  • Can't see relationships between sections
  • Clicking between tabs to compare demand vs gaps
  • Loses the narrative flow
